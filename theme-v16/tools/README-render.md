# The visual gate (`render_check.py`)

## Why this exists

This theme once shipped with a Liquid syntax error on one line of
`snippets/jsonld.liquid`. Every static check passed:

* 46/46 files parsed with python-liquid
* 29 valid section schemas, 19 valid JSON templates, 0 dangling references
* 0 dead links, 0 dead CSS rules, `node --check` clean

And it still rendered in the merchant's real store as **Times New Roman text with
transparent buttons and invisible cards**.

The reason is worth remembering: the syntax error sat in the `<head>` render
chain, so the `:root` token block never reached the page.
Without those custom properties every `var()` in `assets/theme.css` was invalid
at computed-value time, and the whole storefront silently fell back to browser
defaults. Nothing in the stylesheet was broken — the link in the chain was.

**Static analysis cannot see that.** Only a browser can. So `render_check.py` is
now a mandatory gate: `tools/build.py` refuses to produce a zip unless it passes.

## What it does

1. Renders `layout/theme.liquid` (header group → JSON template sections → footer
   group) through python-liquid with Shopify filters and drop objects emulated.
2. Writes the result beside the real `assets/theme.css` and `assets/theme.js`.
3. Opens all 11 page types in headless Chromium at **1280px and 390px**.
4. Scrolls each page the way a person would, so reveal-on-scroll animations fire.
5. Screenshots each page full height into `$RENDER_OUT/shots` (default
   `/tmp/theme-render/shots`).
6. Asserts what actually broke last time:

| Assertion | Catches |
| --- | --- |
| No `Liquid error` text on the page | the original outage |
| `:root` custom properties exist | `css-variables.liquid` missing from the head chain |
| No custom property is defined-but-empty | `--font-body: , ;` reverting text to Times |
| No serif fallback on headings/body/buttons | theme fonts not applied |
| Every button paints a background, border or image | transparent buttons |
| Cards paint a background, border or shadow | invisible cards/FAQ bodies |
| No closed `<dialog>` still visible | missing `:not([open]){display:none}` |
| Scroll-reveal content became visible | sections stuck at `opacity:0` |
| No horizontal overflow at 390px | mobile layout leaks |
| No console/page errors | broken scripts such as unquoted JSON-LD |
| JSON-LD parses as JSON | silent loss of rich results |
| No `⚠missing:` translation markers | t-filter precedence bugs |
| No page under 500px tall | a template that rendered nothing |

## Running it

```bash
bash tools/setup-renderer.sh                                   # once per machine
PYTHONPATH=/home/user/pylibs python3 tools/render_check.py     # the gate
PYTHONPATH=/home/user/pylibs python3 tools/build.py            # verify + render + zip
```

`setup-renderer.sh` documents the workaround this sandbox needs: Playwright's CDN,
`apt-get` and `npx puppeteer browsers install` are all blocked here, but
`@sparticuz/chromium` ships the Chromium binary *inside* its npm tarball along with
the Amazon Linux shared libraries it links against. Paths are overridable with
`RENDER_CHROMIUM`, `RENDER_LIBDIR`, `RENDER_NODE_DIR`, `RENDER_OUT`.

## Looking at the screenshots

The script asserts, but a human still has to look. Open
`/tmp/theme-render/shots/index-1280.png` (a ~8500px tall capture) and skim it.

Known harness limitations, so you do not chase them as theme bugs:

* Placeholder imagery is generated by the harness, not real product photos.
* `{% form %}` and `{% paginate %}` are stripped from the markup by design; the
  form controls inside still render so layout is comparable.
* The theme editor's own chrome (Shopify admin bar, section selection outlines)
  does not exist in this render.
* Merchant settings are the schema defaults unless a template JSON overrides
  them, so the render reflects a *fresh install*, which is exactly the case that
  broke.
