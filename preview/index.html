Round 3 — the render failure, fixed and made impossible to repeat

You sent a screencapture of the theme running in your real store: a Liquid error banner and an almost unstyled page. Here is what was wrong, what it is now, and the test that stops it happening again.

The bug

snippets/jsonld.liquid line 55 put a literal {search_term_string} inside a Liquid output tag. Shopify rejects that outright:

Liquid syntax error (snippets/jsonld.liquid line 55)
Variable '{{ request.origin | append: '/search?q={search_term_string}' | json }}'
was not properly terminated with regexp: /\}\}/

Because the error sat in the <head> render chain, snippets/css-variables.liquid never emitted its :root block. Every var() in theme.css then became invalid, and the whole storefront fell back to Times New Roman with transparent buttons and invisible cards. The stylesheet itself was fine — the link in the chain was not.

Why my earlier checks missed it

The static suite passed 46/46 files, 0 dead links, 0 dead CSS rules. The generic Liquid parser I was using is more permissive than Shopify's, so it accepted the line that Shopify rejects.

That is no longer how a file gets delivered. The theme is now rendered in a real headless browser at 1280px and 390px, screenshotted, and inspected before any zip is produced. The build script refuses to package a theme that fails the visual gate.

The browser gate found three more real bugs

  • The closed mobile-menu <dialog> was visible on every page at every width — a CSS display rule overrides the browser's dialog:not([open]) hide rule.
  • Label filter precedence: {{ label | default: 'key' | t }} applies t to the result of default, so a merchant-set button label rendered as "Translation missing: en.Enrol now" on the primary call to action.
  • The header CTA wrapped to two lines and became a circle on phones; it now hides below 600px, where the sticky buy bar and menu already carry the action.

Two things made permanently safe

  • An empty font setting can no longer blank the store. --font-body: , ; is not "undefined", so var() never uses its fallback — it just silently reverts everything to serif. Both font stacks now have hard fallbacks.
  • Scroll-reveal content can never stay invisible. If the intersection observer does not fire, everything is force-revealed after 3 seconds.

Round 2 — the remaining items, done

Everything I listed as outstanding last time: the code-side polish that was still missing, plus the store-side setup that could only ever be produced as files.

Code Added to the theme

  • Instant search — a ⌘K / / search overlay that queries Shopify's predictive search endpoint and shows products, pages and guides as you type. Images, prices, debounced requests, abortable, live-region announcements. Press Enter and it falls through to the full search page, so it works with JavaScript disabled too.
  • One-tap add to cart on collection and search cards for single-variant, in-stock products. Multi-variant products automatically show “View details” instead. Posts to /cart/add, so it works without JavaScript as well.
  • Review-app slots — the testimonials section accepts @app blocks, so a reviews app can be dropped in from the editor rather than hard-coded.
  • Test suite + build script in tools/: verify.py gates build.py, so a broken release can't be zipped.

Setup New setup/ folder

  • product-import.csv — the single product, fully specified: handle, ₹2,999 / ₹5,000, 25 seats in tracked inventory, digital (no shipping), SEO title + description, and a ~500-word product description. Shopify admin → Products → Import, done.
  • Four policy documents — refund (7-day, matching what the theme promises), privacy (DPDP Act 2023 ready), terms (with a no-earnings-guarantee clause), delivery. These are what the footer, contact page and structured data link to.
  • content-pack.md — testimonial outreach scripts, exact image sizes and shot list, a 90-second video script, and a launch-week checklist.
  • setup/README.md — the order of operations, and what to trim from the policy drafts.
Why a CSV instead of a checklist: a one-character typo in the product handle breaks every buy button on the site, and forgetting Track quantity silently removes the seats-left chips. Importing the file makes all 24 fields exact on the first attempt.

What is left — store-side only

No code work remains. These are the four things that need your Shopify admin and your real content; the files in setup/ do most of the typing for you.

1. Import the product 2 min

  • Products → Import → setup/product-import.csv. Every field is pre-filled: handle, price, compare-at, inventory tracking, digital flag, SEO.
  • Confirm the handle is ai-shopify-business-bootcamp — the theme points at it. Different handle? Change it in Theme settings → Course product.
  • Set the real seat count. The “Only N seats left” chip reads it live.

2. Publish the four policies 10 min

  • Copy each file from setup/policies/ into Settings → Policies, replacing every [BRACKET].
  • The footer, contact page and structured data link to them automatically once they exist — and they're required for Meta/Google ad approval and gateway KYC.
  • Have a lawyer glance at the liability and jurisdiction clauses. They're drafts, not legal advice.

3. Theme settings 5 min

  • WhatsApp number, Instagram, support email, logo, favicon
  • Cohort start date (drives the countdown and Course.startDate)
  • Social share image, 1200 × 630, for WhatsApp link previews

4. Real content your weekend

  • Replace the 3 placeholder testimonials — content-pack.md has the outreach script
  • Add 2–4 student-store screenshots to the results row
  • Upload the instructor photo (800 × 1000) and hero image (1200 × 1500)
